# 1. 문제 정의 및 요구사항 분석

## 1.1 현황 요약

알로스타의 결과지 상담은 **"고객 연락 → 담당자가 일정 확인 → 다시 안내"** 하는 수동 프로세스로 운영된다. 문제 상황을 이해관계자별로 나누고, 증상(겉으로 보이는 문제)과 근본 원인을 분리했다. 증상만 고치면 같은 문제가 다른 형태로 다시 생기기 때문이다.

| 이해관계자 | 증상 (문제 상황에서 언급된 것) | 근본 원인 | 영향 |
|---|---|---|---|
| 고객 | 상담하려면 별도 채널로 먼저 연락해야 함 | 예약 가능한 시간이 고객에게 **공개되어 있지 않음** | 신청 자체가 번거로움 → 잠재 상담 수요 손실 |
| 고객 | 원하는 시간이 꽉 차 있으면 대안 없이 이탈 | 마감 시 **대체 경로(다른 상담사·다른 시간·대기)**가 없음 | 상담 기회와 후속 구매 기회 손실 |
| 고객 | 가족의 검사 결과로 상담받고 싶음 | 시스템이 **계정 = 피검자**라는 가정 위에 있음 | 가족 상담은 예외 처리(수작업)로 흘러감 |
| 운영 | 일정이 겹치거나 예약 누락 | 예약 원장이 사람/메신저에 분산 → **단일 진실 원천(SSOT) 부재**, 동시 요청 제어 없음 | 중복 예약, 고객 신뢰 하락 |
| 운영/상담사 | 예약했는데 당일 고객과 연락이 안 됨 | 예약 후 **사전 리마인드·참석 확인 절차 없음**, 통화 번호가 불명확 | 상담사 시간 낭비(노쇼), 슬롯 낭비 |
| 상담사 | 상담 기록 방식이 담당자마다 다름 | 기록 **양식(스키마)이 없음**, 자유 텍스트 | 이력 승계 불가, 데이터 집계 불가 |
| 경영/운영 | 어떤 제품에 관심 있었는지, 구매로 이어졌는지 모름. 전환율 수동 집계 | 상담 기록과 **커머스 주문이 연결되어 있지 않음**, 전환 정의 부재 | 상담의 사업 성과를 증명/개선할 수 없음 |

## 1.2 핵심 문제 정의

> **상담이 "예약 → 진행 → 기록 → 성과"로 이어지는 하나의 흐름으로 관리되지 않아, 각 단계에서 고객·시간·데이터가 새고 있다.**

각 단계의 누수를 막는 것이 목표다.

| 단계 | 누수 | 개선 목표 (측정 지표) |
|---|---|---|
| ① 예약 | 연락 장벽, 마감 시 이탈, 중복/누락 | 셀프 예약 비율 100%, 중복 예약 0건, **대기→예약 회수율** |
| ② 진행 | 노쇼 | **부재율(노쇼율)** 감소, **참석 확인율** 증가 |
| ③ 기록 | 비표준 기록 | **기록 제출률** 100%, 구조화 필드(관심사·추천 제품·관심도) 채움률 |
| ④ 성과 | 전환 미측정 | **상담 전환율** 자동 집계, 상담사·관심사·제품별 분해 |

## 1.3 가정 (문제에 명시되지 않아 직접 정한 것)

| # | 가정 | 근거 / 영향 |
|---|---|---|
| A1 | 상담은 **상담사가 고객에게 거는 30분 전화 상담**이다 | 현행 방식 유지. 화상 상담은 확장 범위 |
| A2 | 상담사는 분석 서비스별 **전문 분야**가 있다 (예: 음식물 과민증은 특정 상담사만) | 결과지 종류 ↔ 상담사 매칭이 필요 |
| A3 | 결과지는 분석 시스템(LIMS)에서 생성되며, **키트 코드**로 고객 계정과 연결된다 | MVP는 시드 데이터 + 키트 코드 연결로 대체 |
| A4 | 제품 구매는 **자사몰**에서 일어나며, 주문 이벤트를 웹훅으로 받을 수 있다 | 전환 귀속 계산의 전제 |
| A5 | 고객은 국내 고객이며 모든 시간은 **KST** 기준 | 다지역 확장 시 UTC 저장으로 전환 |
| A6 | 가족 결과로 상담 시, 계정 소유자가 **피검자 본인의 동의를 받았다는 확인**이 필요하다 | 건강정보는 민감정보 → 최소한의 동의 근거 확보 |

## 1.4 사용자와 주요 시나리오

- **고객(계정 소유자)**: 본인/가족의 결과를 보고 → 가능한 시간 확인 → 셀프 예약 → 리마인더에 참석 확인 → 상담 후 요약·추천 확인
- **상담사**: 오늘 일정과 참석 확인 여부 확인 → 상담 전 결과지·사전 질문 검토 → 통화하며 같은 화면에서 구조화 기록 → 제출
- **운영 관리자**: 상담사 근무 시간(슬롯) 관리 → 전체 예약 모니터링·예외 처리 → 대시보드로 노쇼/전환 지표 확인
